## 3. 勘查发现但**未**清理的（附理由）

**没有找到真正的死代码。** 用入边分析扫了 200 个源文件（`src/` `server/` `scripts/` `desktop/` `mobile/`），
排除入口文件（`main.jsx`、`app/**`、`server/index.js`、npm script 目标）后：

- 孤儿文件 61 个里，58 个是**入口或测试文件**（测试文件靠 jest/vitest glob 发现，不走 import）；
- 真正既不被 import、也不被 package.json 脚本引用、全仓 grep 也找不到文件名的，只有 1 个：
  `scripts/catalog/ui-profile.js`（6.0 KB，69 行，`UI_PROFILES` 字段契约 + `contractExample()`）。
  - 头部注释写着 *"Proposed UI contract. These profiles do not change the running catalog API."*，
    即一份**未被采用的提案**，唯一一次提交 `ecc077b` 之后再无改动。
  - **建议保留**：它是 mobile 端 `src/lib/fields.js` / `labels.js` 那套字段显隐思路的源头，
    删掉会让「为什么 App 只显示这些字段」失去依据。若要删，先把它抄进 mobile/README.md。

其它看着像垃圾、实际有用的：

- `src/demo/`（20 个组件）——UI Demo 的 6 套设计稿，`demo.html` 入口，仍在跑；
- `scripts/crawler/`（33 个文件）——采集器，全量数据就靠它，虽不是日常入口；
- `docs/plans/` 32 个文件里 26 个是 2026-04 的成对 design/plan，全部已实施完（对应 `docs/15`/`docs/16` 的修复项）。
  它们是历史决策记录，**不建议删**，但可以在 `docs/README.md` 标注「已归档」。

## 5.  `.gitignore` 覆盖核查

- `desktop/build/installer.nsi`（8.3 KB）**被跟踪是对的** —— `.gitignore:14` 的 `build` 规则只匹配目录、

  但公钥证书要进仓库给 App 做信任锚，`mobile/scripts/android-pins.mjs:43` 会读它。
