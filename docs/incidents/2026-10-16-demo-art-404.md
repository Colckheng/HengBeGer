# 2026-10-16 线上 /demo-art 破图事故记录

## 现象

用户贴出线上首页截图：三张世界卡片的位置只剩 alt 文本（「安比生日插画」
「三月七花束插画」「三月七蛋糕插画」），图全裂。站点 theme-orbital「开放图录」。

## 根因（两层叠加）

1. `.dockerignore` 把 `public/demo-art` 与 `public/demo-data` 整目录排除出 Docker
   构建上下文。容器里 `vite build` 时 `public/` 下根本没有 demo-art，`dist/` 里自然也没有。
   原注释「只服务设计预览页 demo.html 的素材，生产入口用不到」是过期判断。
2. `deploy/Dockerfile` 原本还有 `rm -rf dist/demo-art dist/demo-data`，
   即便上下文里有也会被删掉。

连带伤害更隐蔽：`src/open-index/open-index.css` 的 `@font-face` 全部指向
`/demo-art/fonts/*.woff2`，theme-orbital 的字体变量也指向 Archive Sans ——
**全站字体已静默退化成系统字体，不报错也不红屏，只能靠肉眼发现。**

排查时的一个误导点：线上这些地址返回的是 **200 text/html（index.html 679 字节）**
而不是 404。`express.static` 找不到文件时会落到 SPA fallback（`server/index.js:847-849`），
浏览器把 HTML 当图片加载失败，于是只剩 alt 文本。所以「HTTP 200」不代表资源存在。

## 修复

- `.dockerignore` 只排除 `public/demo-art/previews` 与 `public/demo-data`；
  `covers/`、`fonts/` 与根级 9 张插画进入构建上下文。
  这 9 张不是设计预览专用：orbital 世界页 hero 图（`src/demo/AtlasEdition.jsx:46` 的 `copy.art`）
  与条目详情页肖像图（`src/demo/AtlasDetail.jsx:36` + `src/demo/artworks.json`）真的在用。
- 新增 `scripts/trim-dist.mjs`：白名单裁剪 + **引用完整性校验**。
  扫 `dist/` 下所有文本产物里的 `/demo-art/` 引用，缺一个就让构建失败。
  `deploy/Dockerfile` 只留一行 `RUN npm run build && node scripts/trim-dist.mjs`，
  取代原先不可读的 `node -e` 巨无霸。

本机验证：`npm run build && node scripts/trim-dist.mjs` →
`dist ready: files=164 bytes=50906850`（48.5 MB），0 缺失。
预演栈（https://127.0.0.1:8444）三张 covers + 9 张根级插画 + 字体全部 200。

## 教训

1. 前端静态资源缺失在 SPA fallback 下会伪装成 HTTP 200，必须校验 content-type。
2. 字体这类「不报错的退化」要把检查放进构建期，不能依赖肉眼。
3. `.dockerignore` 的排除项要跟着代码走：模块被生产链路 import 后，
   原来的「只有设计预览用得到」注释就成了谎言。
