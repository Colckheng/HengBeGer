# 新Wiki UI需求清单（步骤2，2026-10-08）

本轮范围：基于[87个真实样本](./23-ui-samples-2026-10-08.md)和全量字段统计，确定页面需要呈现的信息、交互和缺失状态。这里是待设计的需求，不表示这些页面、筛选或数据适配已经实现。颜色、字体、布局稿和可点击原型留在步骤3；新数据库接入留在其后。

数据基线为本地2675条记录、18种逻辑类型、23个分组。货币战争S1／S2各自取样；机制文章仅有1＋2篇，已全部纳入。详细字段覆盖率与样本路径保存在[样本JSON](./23-ui-samples-2026-10-08.json)。本轮没有修改数据、业务页面或数据库。

## 1. 需要哪些页面与模块

建议共用站点导航、搜索、筛选、卡片、详情目录和来源说明；详情内容按下列8类组织。它们是信息结构，可复用组件，不必做成8套完全不同的视觉风格。

| 详情结构 | 覆盖数据 | 核心信息 |
| --- | --- | --- |
| 角色 | 绝区零代理人、星铁角色 | 身份标签、属性、技能、成长、影画／星魂、配装、故事 |
| 武器 | 音擎、光锥 | 适用特性／命途、基础与附加属性、精炼／叠影、材料 |
| 套装 | 驱动盘、遗器 | 2／4件效果、部位（有数据时）、推荐角色、故事 |
| 邦布 | 绝区零邦布 | 属性、可用技能组、技能等级、材料 |
| 敌人 | 两款游戏敌人 | 弱点／抗性、等级与难度口径、技能、变体、掉落 |
| 活动时间列表 | 调频、跃迁 | 官方活动／阶段汇总、原始日期、UP角色或装备 |
| 机制文章 | 两款游戏机制 | 目录、公式、表格、插图、版本适用范围和署名 |
| 货币战争 | 两赛季角色、羁绊、物品、策略、环境 | 赛季常驻；角色的前后排技能、羁绊层数；其余按效果与属性展示 |

货币战争这一类内部必须保留角色、羁绊和效果型条目的区别。18种类型都能复用基础框架，但不能强制套上同一组详情字段。

### 页面级需求

| 页面／区域 | 必需行为 | 验收方式 |
| --- | --- | --- |
| 分类入口 | 绝区零、星铁、货币战争；展示对应类别与数量。货币战争有S1／S2切换 | 从入口可找到全部23个分组；切赛季后数量与结果同步 |
| 分类列表 | 名称搜索、类别专属筛选、结果数、分页；同名项可区分 | 搜索三月七或阿哈不会只保留一条；空结果可清除筛选 |
| 详情页 | 可独立访问的稳定地址；面包屑、类型化内容、目录和关联条目 | 刷新可恢复详情；返回列表保留筛选与页码 |
| 数据说明 | 来源、采集时间、补充核验范围、适用等级；异常提示靠近受影响字段 | 伊埃斯不能显示“已全部核验”；反重子不同等级的数值不会混为一组 |

稳定身份以完整类别＋ID为准，货币战争包含赛季。名称、图片或alias相同都不构成合并依据。类别归属以数据目录／category为准：货币战争部分记录的`game`实际为`hsr`，不能仅用该字段归类。

## 2. 数据能支持到什么程度

下文采用三种标记：**可直接用**＝已有结构化字段且语义没有发现明显疑点；**需整理**＝正文中有内容，但需要按实际章节／表格提取和校验；**需核验／补充**＝当前缺失、存在矛盾或仅有参数，不能假定已经具备。字段存在只代表有数据，并不等于游戏事实已全面核验。

| 数据现状 | 对UI的约束 |
| --- | --- |
| 图片可用2518／2603，85条缺图；69条活动与3篇机制不计入此分母 | 图鉴提供固定比例占位；活动和文章不强制安排头图。这个统计不保证正文中的远程插图可用 |
| 驱动盘只有12／30有稀有度 | 稀有度不作为默认主筛选；详情缺值写“未提供”，不能全部补S |
| 星铁角色阵营85／99；绝区零敌人属性274／364，评级与阵营314／364 | 标签按有值展示；“未提供”可进入筛选，缺失不得视为零 |
| 星铁敌人590条有明确Lv.80字段；74条保留种子来源；弱点619／664 | 数值附等级／难度和来源。弱点缺失不是“无弱点”；种子记录的等级从其正文独立确认 |
| 货币战争物品稀有度：S1为5／160、S2为6／109 | 首版按物品类型筛选，稀有度只作可选信息 |
| 货币战争环境没有统一结构化类型；仅S1的20／84条有`关联`串，S2无此字段 | 不凭“邀请／概念股”后缀自动宣称完整分类或关系图 |
| 大量详情来自Markdown，部分还保留历史正文或来源站动态标记 | 做受控的展示整理；不把原Markdown直接当成已完备的交互式数据模型 |

## 3. 每类列表、筛选与详情需求

以下均为首版需求。排序首先支持稳定的名称／ID顺序；数值排序必须同等级、同属性语义，当前不提供跨口径战力排名。所有分类支持搜索名称和ID；有可靠alias时可作为搜索补充，不能覆盖主名称或身份。

## 4. 通用组件与状态规则

| 组件／状态 | 需求 |
| --- | --- |
| 图片 | 固定占位区域，按角色／装备／敌人使用合适裁切；无图和加载失败都有回退；图片不承载唯一身份信息。不要用别的形态图片随意补缺 |
| 身份与标签 | 完整名称可换行；消歧优先命途／形态／星阶，再使用ID；保留+、++、★、标点。展示层可去掉已识别的排版标签，保留原始字段供核对 |
| 数值表 | 名称、数值、单位、等级、来源口径共同呈现；0不等于空；百分比不当普通整数；未知值用“未提供”，待核验与已知值分开 |
| 可切换技能 | 只展示实际有数据的技能组、等级、精炼／叠影档位；换档后描述和数值同步；材料不因为切换技能而误标为全角色总成本 |
| 详情目录 | 按实际模块生成，跳过空章节；层级清楚；同名章节来自不同来源时有可识别标题，不能产生重复锚点 |
| 关联条目 | 确认游戏、类别、赛季和ID后才生成站内链接；正文旧目录如character／role／item须映射。当前没有普通材料物品分类时保留名称和数量，不生成不存在页面 |
| 文本与公式 | 安全呈现Markdown与数学公式；来源站标签按白名单语义转换。gridfightinfo有明确type／id才尝试在同赛季解析；失败显示可理解的未解析引用，不能把整段效果删空 |
| 数据说明 | 折叠区保存来源、采集时间、补充核验范围；影响判断的缺图／未知等级／冲突在附近提示。技术哈希和原始JSON不放主阅读流程 |
| 加载、错误、空结果 | 加载状态保持布局；请求失败可重试；零结果可清除筛选；条目不存在时能返回类别；错误不伪装成“没有该类数据” |

### 日期与版本特别规则

1. 起始时间为空但有“正式开服后”时展示原文；结束为空且`end_open=true`展示“长期”，与“未提供结束时间”区分。
2. “采集时来源状态”和按日期计算的“当前状态”必须区分。来源时区不明或时间冲突时，首版仅展示原文时间与来源状态，不自动承诺正在开放／倒计时。
3. `version`在不同来源中含义不同：有的为游戏版本，有的是米游社内容修订号或内容哈希。不能把角色`version: 83`展示为“游戏83版本”。仅明确是活动／游戏版本的字段用于版本标签与筛选。
4. 官方UP表的“内容ID”与历史汇总的“游戏ID”属于不同命名空间。需要映射后才能跳转；不能直接拿内容ID请求游戏角色详情。
5. 3.4上半的“长期”属于来源阶段记录，不足以推断其中每个UP条目永久开放。

### 来源与数值冲突规则

当摘要字段、保留正文和补充核验不一致时，先按来源及等级分开呈现；没有足够证据时不得自动选择较大值、较新采集时间或自动算平均。补充核验只作用于其声明的字段，例如幽浮布冲击力、遗器套装效果；不能给整条记录盖“完整核验”标记。

反重子详情应将“当前摘要：Lv.80／难度组1”和“历史正文快照：Lv.95”明确分开。正文中关于原站可调等级的描述，不等于本站已经具备相同等级计算能力。
